# خطة الترقية الرياضية العالمية — بسلاسة

## المبدأ الحاكم

تظل «بسلاسة» غرفة عمليات مدرس حية. الأدوات الرياضية تقترح وتنفذ بسرعة، لكنها لا تبدأ لعبة أو تمنح نقطة أو تغير مسار الدرس دون قرار المدرس. كل مخرج رياضي يجب أن يكون قابلاً للربط بالشريحة الحالية، والإخفاء، والتراجع، والحفظ، والتصدير.

## المقارنة المرجعية

| المرجع | القدرات الملحوظة | ما يُستفاد منه في بسلاسة | ما لا يُنسخ |
|---|---|---|---|
| GeoGebra | حاسبات ورسوم تفاعلية، هندسة، جبر، إحصاء واحتمالات، موارد صفية، ومتابعة تقدم لحظية [1] | محرك أدوات رياضيات متعدد المجالات وربط النشاط بالتعلم | لا نستبدل غرفة عمليات المدرس بمنصة موارد مستقلة |
| Desmos Studio | رسوم بيانية، حاسبة علمية، هندسة، 3D، Notebook، sliders وتفاعلات قابلة للسحب [2] | محرر رسوم سريع وتفاعل مباشر مع الدوال والمتغيرات | لا نضع الرسم البياني خارج سياق الشريحة والحصة |
| Math Whiteboard | كتابة رياضية، handwriting، رسم بياني، sliders، CAS، إدراج PDF، وتعاون رياضي [3] | Math canvas موحد، أدوات كتابة ومعادلات وتصدير/تعليق على PDF | التعاون عندنا يبدأ بقرار المعلم ولا يفتح تعديلات مجهولة |
| SMART Board | split-screen، ملاحظات حية، تعدد مصادر، مشاركة أعمال الطلاب، وطبقة حبر قابلة للحفظ [4] | ربط الشريحة والسبورة والأصول في مساحة واحدة، مع حفظ لقطات | لا نضيف تشعباً يشتت المدرس أثناء الحصة |

## المخرجات الرئيسية

### 1. محرك سبورة رياضية

إضافة طبقات مرتبطة بـ`lessonId + ideaId + step` بدلاً من سبورة عابرة. الطبقات المقترحة هي الرسم الحر، المعادلات، الشبكات والمحاور، الهندسة، القياسات، التعليقات، والنتائج المحفوظة. لكل طبقة visibility وlocked وzIndex وcreatedBy وcreatedAt.

### 2. أدوات الرياضيات

تشمل الآلة الحاسبة الأساسية والعلمية، محرر الكسور، النسب والمئوية، تبسيط التعابير، حل المعادلات، المحاور والإحداثيات، رسم الدوال، sliders، خط الأعداد، القياس، الأشكال الهندسية، الإنشاءات، التحويلات، مساحة ومحيط وحجم، المثلثات، الإحصاء، الاحتمالات، الجداول، والمصفوفات.

### 3. ربط الشريحة

عند الانتقال إلى شريحة جديدة تُحمّل annotations الخاصة بها. يستطيع المدرس اختيار «مسح مؤقت» أو «الاحتفاظ بطبقة الشرح» أو «نسخ الشرح إلى الشريحة التالية». لا يمسح الانتقال البيانات المحفوظة، ولا يؤدي reload إلى فقدان الرسم.

### 4. تطوير الألعاب

لكل لعبة metadata تعليمية: skill، difficulty، timeLimit، gradeBand، questionSource، learningObjective. تُضاف أوضاع رياضيات مثل سباق المحاور، تحدي الكسور، مطابقة الشكل والخاصية، معادلة السرعة، بناء الشكل، تخمين الدالة، واحتمالات الصندوق. تبقى كل لعبة تحت تحكم المعلم، مع منع تكرار الطالب والمكافأة والسؤال.

### 5. التقارير وPDF

الحد الأدنى المطلوب هو تصدير PDF للحصة كاملة، تقرير الطالب، نتيجة اللعبة، الشريحة مع شرح السبورة، ورقة الأسئلة، ورقة الإجابات، وسجل الأنشطة. يجب أن يكون التصدير قابلاً للتنزيل فوراً، مع حفظ metadata واسم الدرس والتاريخ والصف والفكرة والشريحة.

## تصميم التنفيذ المرحلي

1. استخراج نموذج رياضي مستقل واختباره دون UI.
2. إضافة state للـslide annotations مع migration آمنة وfallback للبيانات القديمة.
3. بناء MathToolbar وMathToolsPanel وإدخالهما في `IframeStage` دون تغيير عقد iframe الحالي.
4. تطوير الرسم البياني والهندسة على SVG/Canvas خفيف، مع استخدام Math.js للحسابات فقط عند الحاجة، وعدم إدخال CAS كامل في كل render.
5. بناء تصدير PDF مشترك يعتمد على jsPDF/html2canvas للمخرجات الحالية، مع مسار server-side لاحقاً للتقارير الرسمية الثقيلة.
6. ربط الألعاب بالمهارة ومصدر السؤال وإضافة أنشطة رياضية صغيرة قابلة لإعادة الاستخدام.
7. إضافة اختبارات pure functions، ثم browser tests، ثم مصفوفة السيناريوهات والانحدار.

## معايير القبول

| المجال | معيار القبول |
|---|---|
| ربط الشريحة | الرسم يعود عند الرجوع للشريحة نفسها ولا يظهر على شريحة أخرى |
| الرياضيات | الكسور والحسابات والهندسة تعطي نتائج صحيحة في الاختبارات النقية |
| الأداء | لا يعاد رسم اللوحة كاملة عند كل تغيير غير متعلق بها |
| الحصة الحية | كل الأدوات قابلة للإيقاف والإخفاء ولا تعطل iframe |
| التصدير | PDF عربي مقروء، يحمل اسم الدرس والصف والزمن، ولا يقطع الجداول الأساسية |
| الألعاب | لا سؤال مكرر، لا مكافأة مزدوجة، ولا طالب غائب |
| التراجع | undo/redo يعملان على الرسم والأشكال والعناصر الرياضية |
| الوصولية | لوحة المفاتيح وRTL وreduced-motion تعمل دون فقد الوظائف |
