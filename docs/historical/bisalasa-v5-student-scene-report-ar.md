# تقرير V5 — فصل مشهد الطلاب عن غرفة عمليات المدرس

## ملخص التنفيذ

تم تنفيذ التعديل الجوهري المطلوب في منصة بسلاسة: أصبحت هناك طبقتان واضحتان. الطبقة الأولى هي **غرفة عمليات المدرس**، وتحتفظ بالشريط الجانبي والتليبرومبتر وأزرار AI وNotes والألعاب والتقارير والإعدادات والبانلز العادية. الطبقة الثانية هي **مشهد الطلاب/OBS**، ولا تعرض إلا الشريحة التعليمية والسبورة التعليمية وما يختاره المدرس ليكون جزءاً من الشرح.

يمكن فتح المشهد الطلابي من الرابط التالي داخل نسخة المنصة:

```text
/?view=student
```

كما أضيف زر أخضر في شريط معاينة الطالب لفتح هذا المشهد في نافذة مستقلة جاهزة للمشاركة مع Zoom أو OBS.

## قاعدة الظهور الجديدة

> أي بانل عادي يبقى في موضعه الحالي. أما AI وNotes والتحليل والتقارير والإعدادات وMoodle ومحرر الدرس فهي أدوات خاصة بالمدرس، ولذلك تُحجز في مساحة التليبرومبتر/العمود الإداري ولا تدخل مساحة الكانفاس الطلابية.

| العنصر | غرفة المدرس | مشهد الطلاب |
|---|---:|---:|
| الشريحة التعليمية | ظاهر | ظاهر |
| السبورة التعليمية | ظاهر | ظاهر |
| التليبرومبتر | ظاهر | مخفي |
| أزرار AI الأربعة | ظاهر | مخفي |
| لوحة AI | ظاهر في مساحة المدرس | مخفية |
| Notes | ظاهر في مساحة المدرس | مخفية |
| محرر الدرس | ظاهر في مساحة المدرس | مخفي |
| Moodle والإعدادات والتقارير | ظاهرة عند فتحها | مخفية |
| البانلز العادية مثل الطلاب والفصول والألعاب | لم تتغير | مخفية في المشهد النظيف |
| MathTools والأصول المساعدة والمقابض | متاحة للمدرس | مخفية في studentView |
| الاحتفالات التعليمية | تعمل في غرفة المدرس وفق النظام الحالي | تبقى جزءاً من العرض عندما تكون داخل المشهد التعليمي |

## العزل على مستوى SSR

لم يُنفذ العزل على مستوى CSS فقط. تم فصل `src/app/page.tsx` إلى Server Wrapper يقرأ `view=student` أثناء SSR ويمرر القيمة إلى `src/app/page-client.tsx`. لذلك لا يخرج HTML المشهد الطلابي أصلاً وهو يحتوي على نصوص أو أزرار AI وNotes أو الشريط الجانبي قبل تشغيل JavaScript.

أصبح `IframeStage` يقبل `studentView`. في هذا الوضع يتم إخفاء أدوات الرياضيات والأصول المساعدة وزر الإغلاق ومقابض تغيير الحجم ومؤشر التكبير، بينما تبقى الشريحة والسبورة التعليمية. الوضع العادي لا يمرر `studentView` ولذلك لا تتغير غرفة المدرس.

## محرر الدرس

أضيفت لوحة **محرر الدرس** إلى الشريط الجانبي. يستطيع المدرس اختيار أي خطوة وتعديل العنوان والسكريبت والنوتس، ثم حفظ التعديل في `manifestJson` عبر عقد SQLite الحالية. بعد الحفظ يعاد تحديث manifest المحلي مع الحفاظ على موضع الخطوة والفكرة الحاليين، ولا يفقد المدرس مكانه أثناء الحصة.

تحتوي اللوحة أيضاً على زر **حلل الدرس بـAI** وزر **تحسين السكريبت**. النتائج تظهر كاقتراحات للمراجعة فقط. لا يُكتب أي اقتراح على الدرس تلقائياً؛ الاعتماد يتم بضغط المدرس، ثم يمكن حفظه صراحةً. يحفظ تحليل الدرس في `AppSettings` تحت `lessonContext` مرتبطاً بمعرّف الدرس.

## الحفاظ على الفلسفة

لا يدخل الطالب إلى المنصة ولا يتحكم في القرار. مشهد الطلاب هو مخرج عرض فقط. أدوات AI لا تنفذ تلقائياً ولا تظهر في المشهد. فشل AI أو Moodle أو Telegram لا يمنع تشغيل الدرس محلياً أو استخدام السبورة أو إنهاء الحصة.

## التشغيل

```bash
pnpm install
mkdir -p data
DATABASE_URL='file:./data/custom.db' pnpm exec prisma db push
pnpm exec prisma generate
DATABASE_URL='file:./data/custom.db' pnpm run build
PORT=3010 NODE_ENV=production DATABASE_URL='file:./data/custom.db' pnpm start
```

رابط المعاينة بعد التشغيل هو `/` للوضع العادي، و`/?view=student` لمشهد الطلاب.
