# تقرير الترقية الرياضية — بسلاسة

## الملخص التنفيذي

تم تنفيذ ترقية عملية ومتكاملة للطبقة الرياضية مع الحفاظ على فلسفة «غرفة عمليات المدرس». أصبحت المنصة تحتوي على مختبر رياضيات داخل المسرح، ومحرك حسابات مستقل قابل للاختبار، وحفظ شرح السبورة لكل شريحة وفكرة، ومركز تقارير وPDF، ومهمات رياضية قصيرة قابلة للتحكم من المعلم.

لم تتحول الأدوات إلى نظام تلقائي يقرر بدلاً من المعلم. فتح الأداة، إدراج النتيجة، اختيار الطالب، منح النقاط، وحفظ التقرير كلها ما زالت تحت قرار المدرس.

## ما تم تنفيذه

| المجال | التنفيذ الفعلي |
|---|---|
| الحساب الآمن | حاسبة تدعم الأقواس و`×` و`÷` والأولوية الحسابية، مع رفض أي نص غير حسابي أو تنفيذ كود |
| الكسور | قراءة الكسر والعشري، الاختزال، الجمع والطرح والضرب والقسمة، الناتج المختلط والعشري |
| الهندسة | مستطيل ودائرة ومثلث، معاينة SVG، مساحة ومحيط، فيثاغورس، حجم متوازي المستطيلات |
| الرسم البياني | رسم دالة خطية `y = mx + b` داخل SVG مع إدراج وصف الدالة على السبورة |
| الإحصاء | المتوسط والوسيط والمنوال لمجموعة قيم قابلة للإدراج في الشريحة |
| الوحدات | تحويل ملم/سم/متر/كم مع نتائج قابلة للإدراج |
| المهمات | مهمات كسور وهندسة ومعادلات، تحقق من الإجابة، عداد نتيجة، وتسجيل النقاط فقط عند وجود طالب مختار |
| ربط الشرائح | snapshot لكل `lesson + idea + step`، واستعادة عند الرجوع، مع منع تسرب الشرح بين الشرائح |
| الإدراج على السبورة | النتائج الرياضية تدخل كعنصر نصي ضمن Undo/Redo الحالي |
| PDF الشريحة | حفظ منطقة العرض والشرح الحالي كـPDF من غرفة العمليات |
| PDF الدرس | مركز التقارير يوفّر نسخة طالب ونسخة مدرس باستخدام مسار PDF الموجود في المشروع |
| PDF الصف والحصة | ملخص صف يحتوي الطلاب والنقاط والأسئلة والمشاركة والحضور |
| تقرير الطالب | أضيف PDF بجوار JSON مع إحصاءات الطالب والأنشطة واللقب والهدايا والجلسات |
| مركز التقارير | panel رسمي في الشريط الجانبي يضم كل مسارات PDF وفتح تقرير الدرجات المتقدم |

## المقارنة المرجعية

استُخدمت GeoGebra كمرجع لتعدد مجالات الرياضيات والموارد الصفية والحاسبات التفاعلية [1]، وDesmos كمرجع للرسم البياني والتفاعل مع النقاط والـsliders والهندسة [2]، وMath Whiteboard كمرجع للسبورة المتخصصة في الرياضيات والـCAS وإدراج PDF [3]، وSMART كمرجع لفكرة عرض المحتوى والشرح في مساحة واحدة مع حفظ طبقة الحبر [4].

الفرق الجوهري أن بسلاسة لا تضع هذه القدرات في منصة منفصلة عن الحصة. كل أداة مرتبطة بالشريحة، وكل مكافأة أو نشاط يحتاج قرار المدرس، وكل تصدير يخرج من غرفة العمليات نفسها.

## التحقق الواقعي

أعيد تشغيل خادم الإنتاج من Build نهائي، وأعادت الصفحة الرئيسية وصفحة الدرجات HTTP 200. في المتصفح الداخلي ظهر مختبر الرياضيات فوق الشريحة، ونُفذت العمليات التالية بنجاح: `(3+5)×2 = 16`، و`3/4 + 1/2 = 5/4`، ومساحة المستطيل 8×5 = 40 ومحيطه 26، ومتوسط المجموعة 5 ووسيطها 3 ومنوالها 3، وتحويل 150 سم إلى 1.5 متر، ومهمة الكسور `1/2 + 1/4` بإجابة 3/4.

اختُبر حفظ snapshot للشريحة، وظهر عنصر للشريحة الأولى وعنصر صفر للشريحة الثانية، ثم عاد الناتج عند الرجوع إلى الشريحة الأولى. كما اختُبر تصدير الشريحة والسبورة PDF بعد معالجة مشكلة `oklab` في html2canvas، وظهر إشعار نجاح، وتم التحقق من وجود الملف `شريحة-1-رياضيات.pdf` بحجم 25,139 بايت في مجلد التنزيل.

## الحدود المقصودة

الرسم البياني الحالي يركز على الدوال الخطية، وليس بديلاً عن CAS كامل أو محرر 3D. أدوات الهندسة الحالية تعليمية سريعة وليست نظام إنشاءات هندسية برهانية كاملاً. تصدير الشريحة يستخدم التقاط DOM/CSS مع fallback محايد، ولذلك ينبغي في إصدار لاحق إضافة مسار server-side أو renderer مخصص للحصول على fidelity أعلى للشرائح المعقدة. كما أن snapshot الحالي محلي في المتصفح؛ التخزين السحابي أو التزامن بين أجهزة الطلاب يحتاج طبقة حسابات وتخزين مشتركة منفصلة.
