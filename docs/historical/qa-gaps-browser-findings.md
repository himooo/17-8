# Browser QA — gaps round

- Build production الأخيرة على `http://127.0.0.1:3012/` أعادت HTTP 200.
- ظهرت أزرار «المنهج»، «محرر الدرس»، «مساعد AI»، «التقارير»، «الطلاب»، «Moodle/التكاملات» ضمن الشريط المدرسي.
- المشهد الابتدائي لا يعرض أي panel خاص بالطلاب أو AI داخل canvas.
- محاولة click الفهرسي على «المنهج» لم تغيّر الحالة في Browser harness الداخلي؛ هذا يتطابق مع القيد المسجل سابقاً: HTML/JS/chunks تعمل لكن React event delegation لا يستجيب للنقر الاصطناعي في هذا harness.
- لذلك استُخدمت اختبارات API وsmoke وstatic privacy للتحقق الوظيفي، مع استمرار فصل Student View عبر `?view=student`.
## PDF عربي — نتيجة فحص بصري

تم فحص PDF التجريبي مرتين. النسخة الأولى بعد إضافة Live App كانت حروفها العربية مفككة. تجربة إزالة reverse من ArabicReshaper حسّنت بعض الترتيب لكنها أبقت النص غير مقروء بصرياً؛ لذلك سُجلت المشكلة كفشل حقيقي في مسار PDF العربي، ولن تدخل الحزمة النهائية قبل إصلاح RTL/Arabic rendering وإعادة الفحص البصري.
## PDF عربي — الإصلاح النهائي

تم اختبار ثلاث حالات. السبب العملي كان إسقاط glyphs العربية عند `subset:true` مع النص المشكّل. الإصلاح المقبول أصبح: ArabicReshaper + bidi-js + Amiri-Regular مع `embedFont(..., { subset: false })`. المعاينة البصرية الأخيرة أظهرت الحروف العربية متصلة ومقروءة، كما ظهرت أقسام Moodle وLive App دون قص. أداة `pdftotext` تعرض Arabic presentation forms بترتيب بصري معكوس، وهو سلوك استخراج RTL لا يعكس شكل الصفحة المرئي؛ معيار القبول هنا هو العرض البصري داخل PDF.
## Browser QA — build Copilot/RTL الأخيرة

أعيد تحميل `3012` بعد build الأخيرة؛ عناصر «محرر الدرس» و«مساعد AI» و«التقارير» ظاهرة في الشريط. إعادة click على «المنهج» لم تغير الحالة في Browser harness الداخلي. لا توجد دلالة على خطأ build أو route، لأن الصفحة والـchunks أعادت 200، وLessonEditor/AI/Live Sync مرّت باختبارات API وsmoke. سُجل القيد نفسه بدلاً من إعلان نجاح تفاعل لا ينفذه harness.
