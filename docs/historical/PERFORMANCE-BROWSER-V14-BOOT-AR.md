# قياس boot النظيف بعد V14

تم فتح `http://127.0.0.1:3036/` في متصفح Chromium بعد build production جديد، في حالة لا توجد فيها لوحة هدايا أو احتفال مفتوحة.

| المؤشر | القياس |
|---|---:|
| عدد الموارد | 48 |
| DOMContentLoaded | 44ms |
| load event | 929ms |
| navigation transferSize | 12,774 bytes |
| الصوت عند boot | 0 ملف |
| صور الهدايا عند boot | 0 ملف |
| موارد JavaScript | 32 script resources |
| إجمالي الموارد المرصودة | 2,504,939 bytes تقريباً |
| أكبر chunk مرسل | 330,293 bytes |
| page chunk | 130,555 bytes |

## النتيجة

تم منع التحميل غير المقصود للهدايا والصوت أثناء boot بنجاح. أصبح تحميلهما مرتبطاً بفتح اللوحة/الاستخدام، كما أن صور الهدايا أصبحت WebP بحجم إجمالي يقارب 0.62MiB بدلاً من 2.80MiB، مع إبقاء PNG للتوافق والاحتياط. ما زال إجمالي JavaScript يحتاج تدقيقاً لاحقاً، لأن Next يرسل chunks مشتركة كبيرة إلى مسار shell؛ لذلك ستستمر مراجعة split points للمكتبات الثقيلة، لكن المشكلة الحقيقية في الأصول تم عزلها وإصلاحها.
