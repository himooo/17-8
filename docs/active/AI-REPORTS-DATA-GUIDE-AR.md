# دليل الذكاء الاصطناعي والتقارير ودورة بيانات الطالب

**آخر تحديث:** 15 أغسطس 2026

## 1. الهدف

تجمع هذه الوثيقة دورة البيانات من لحظة تعريف الطالب أو الدرس، مروراً بالسؤال أو اللعبة أو Moodle، وحتى التقرير العربي وTelegram. كما تشرح أين يستخدم AI، وما الذي يظل تحت قرار المدرس، وما الذي تم اختباره فعلياً.

## 2. دورة البيانات

```text
درس/Manifest
  ↓
فكرة حالية + مصدر سؤال
  ↓
سؤال أو لعبة أو نتيجة Moodle
  ↓
Student / StudentActivity / Session / MoodleResult
  ↓
تجميع الطالب والفكرة والصف
  ↓
Grades + PDF + Telegram
```

كل حدث مهم يجب أن يحمل studentId أو moodleUserId عندما يكون ذلك متاحاً، وlessonKey/ideaKey إذا كان السؤال مربوطاً بالمحتوى. إذا لم يوجد tag أو idea mapping، يحفظ على مستوى الدرس أو في `lesson_unmapped` بدلاً من وضعه في فكرة خاطئة.

## 3. AI الاختياري

AI ليس مساراً إلزامياً لتشغيل غرفة العمليات. يمكن إيقافه بالكامل. عند تشغيله، يدير المدرس مفاتيح providers من `AiPanel.tsx`، مع label وpriority وmodel وحالة تفعيل. لا تعاد القيمة الخام للمفتاح إلى المتصفح بعد حفظه، وتستخدم `src/lib/ai-key-crypto.ts` تشفير AES-256-GCM.

يدعم المسار الحالي:

| الوظيفة | الاستخدام |
|---|---|
| تحليل الدرس | استخراج الأفكار والموضوعات وصعوبات محتملة |
| توليد الأسئلة | اقتراح أسئلة مرتبطة بفكرة أو درس، مع مراجعة المدرس |
| Smart Context | بناء سياق محدود من الدرس والفكرة دون كشف بيانات ممنوعة |
| Copilot المدرس | اقتراح خطوة أو تدخل أو صياغة شرح |
| Model discovery | عرض النماذج عندما يوفر provider endpoint للقائمة |
| Rotation | استخدام مفتاح أعلى أولوية متاح ثم الانتقال عند limit/failure |

الاختبارات الحالية تستخدم mock AI provider. لم يُعتبر Gemini الحقيقي مختبراً إلا بعد أن يضيف مالك التطبيق مفتاحه ويشغل اختباراً مستقلاً. لا ينبغي إرسال اسم الطالب أو معرفاته أو ملاحظات خاصة إلى provider إلا بعد sanitizer وسياسة خصوصية واضحة.

## 4. العدالة التعليمية

لا يجوز لـAI أن يغير مصدر السؤال الذي اختاره المدرس أو يحول سؤالاً من فكرة إلى أخرى دون إظهار ذلك. إذا اقترح AI سؤالاً جديداً، يجب أن يحمل lesson/idea context واضحاً ويحتاج إلى اعتماد المدرس قبل استخدامه في الحصة. إذا فشل provider، لا تتوقف اللعبة أو التقرير المحلي؛ يعود النظام إلى بيانات المنهج أو mock/fallback المحدد.

## 5. التقرير الموحد

التقرير الموحد يجمع:

| المصدر | الحقول الأساسية |
|---|---|
| الطالب | الاسم، الفصل، الغياب، النقاط، الصحيح، الخطأ، المحاولات، الدقة |
| الجلسة | البداية، النهاية، snapshot، delta، participation |
| اللعبة | اسم اللعبة، الطالب/المجموعة، الأسئلة، النقاط، النتيجة |
| النشاط | النوع، الوصف، pointsDelta، metadata، الوقت |
| Moodle | activity، attempt، submission، grade، question result، status |
| الواجب | total، answered، correct، wrong، completion، success rates |
| التدخل | الفكرة، الطالب، نوع التفاعل، هل تغير الوضع بعد التدخل |

الواجب الموسوم يقسم الأسئلة حسب الفكرة. الواجب غير الموسوم يظل على مستوى الدرس. يظهر الطالب الذي لم يسلم بحالة `not_submitted` بدلاً من إسقاطه من التقرير.

## 6. النسب

يجب تفسير النسب بوضوح. `completionPct` يقيس answered/total. `successOnAnsweredPct` يقيس correct/answered. `successOnTotalPct` يقيس correct/total. لا تخلط بين إجابة صحيحة في لعبة ونسبة Moodle إلا إذا ظهر مصدر النتيجة في التقرير.

## 7. PDF وTelegram

يستخدم Telegram مساراً منفصلاً عن التخزين المحلي. عند نجاح التوليد، يجب أن يحتوي PDF على اسم الطالب/الصف، الفترات، المصادر، والإحصاءات المهمة. يجب فحص النص العربي بصرياً، لا الاكتفاء بحالة HTTP أو حجم الملف. عند فشل Telegram، يظل PDF والتقرير المحليان متاحين.

## 8. الخصوصية

AI وMoodle والنوتس والتقارير الخاصة تظل ضمن مساحة المدرس. وضع الطالب لا يحمل هذه اللوحات. لا توضع أسرار provider أو Moodle أو Telegram في manifest أو localStorage المكشوف أو response للمتصفح. تستخدم الطلبات الخارجية أقل قدر ممكن من بيانات الطالب، ويجب تنظيف النصوص قبل إرسالها إلى AI.

## 9. الاختبارات الحالية

تم اختبار AI mock وlimits/rotation، والتقارير الموحدة وتقارير الفصل الكبير، وMoodle homework، Telegram PDF، وprivacy smoke. كما نجحت master audit في فحوص provider rotation، وفصل تشفير Moodle وTelegram، وعقد التقرير الموحد.

لإعادة الاختبار:

```bash
env BASE=http://127.0.0.1:3032 node scripts/ai-mock-e2e.cjs
env BASE=http://127.0.0.1:3032 node scripts/ai-limits-e2e.cjs
env BASE=http://127.0.0.1:3032 node scripts/reports-unified-smoke.cjs
env BASE=http://127.0.0.1:3032 node scripts/reports-large-class-smoke.cjs
node --experimental-strip-types scripts/telegram-report-smoke.ts
```

## 10. حدود واضحة

AI الحالي اختيارياً ومشروط بمفتاح المستخدم. Telegram يحتاج إعداد bot حقيقي. Moodle لا يرسل كل event إلى بسلاسة من تلقاء نفسه دون plugin/relay؛ المسار الأساسي هو Web Services + adaptive polling. SQLite مناسب للتشغيل المحلي الفردي، ويحتاج تشغيل متعدد المستخدمين إلى قاعدة وخطة صلاحيات مختلفة.
