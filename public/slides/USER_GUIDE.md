# دليل المدرس — بسلاسة

**الإصدار المرجعي:** 16 أغسطس 2026 (جولة الإصلاحات الأمنية وقاعدة البيانات)

> هذا الدليل يصف الحالة الحالية للمنصة. التفاصيل المعمارية لبناء الشرائح موجودة في `VIBE_CODING_CONTRACT.md`، والتشغيل المختصر في `QUICKSTART.md`، والمرجع الكامل لكل المكونات في `BISALASA-COMPLETE-DOCUMENTATION-AR.md`.

## 1. فلسفة التشغيل

بسلاسة غرفة عمليات محلية للمدرس أثناء الحصة. الشريحة تُعرض في الوسط، ويستخدم المدرس Zoom أو OBS إذا أراد مشاركة العرض. Moodle يظل مصدراً للسحب والتحليل، والطالب لا يحتاج إلى تسجيل الدخول إلى بسلاسة في النموذج الأساسي.

المدرس يقرر متى يبدأ السؤال، ومن يجيب، وهل الإجابة صحيحة، ومتى يمنح النقاط أو الهدية، ومتى يبدأ اللعبة أو الاحتفال أو التدخل على فكرة معينة. لا تستبدل المنصة قرار المدرس بقرار آلي صامت.

## 2. مناطق الواجهة

| المنطقة | الاستخدام |
|---|---|
| منطقة العرض | iframe للشريحة، والتنقل بين الخطوات والأفكار |
| التليبرومبتر | script الشرح وملاحظات المدرس، ولا يظهر في وضع الطالب |
| الشريط الجانبي | المنهج، الطلاب، المجموعات، النوتس، AI، Moodle، الإعدادات والتقارير بحسب الحالة |
| الشريط السفلي | التنقل، مصدر السؤال، الألعاب، اختيار الطالب، التقييم، الصوت والاحتفال |
| السبورة | طبقة فوق الشريحة للكتابة والرسم الرياضي |
| وضع الطالب | معاينة بسيطة بلا لوحات AI أو النوتس أو التقارير أو إعدادات المدرس |

اللوحات الثقيلة محملة كسولاً. اللوحات الخاصة بالمدرس لا تُحمل في وضع الطالب، بينما تبقى عناصر العرض العادية داخل غرفة المدرس في مواضعها الطبيعية.

## 3. التشغيل الأول

ابدأ التطبيق، ثم أنشئ فصلاً أو اختر فصلاً موجوداً. أضف الطلاب يدوياً أو باستيراد جماعي، ويمكن إضافة طالب بلا فصل ونقله لاحقاً. استورد درس HTML صالحاً أو درساً مبنياً على manifest. اختر الدرس النشط، ثم ابدأ جلسة الحصة.

```bash
cd bisalasa-full-audit
pnpm install
pnpm exec prisma generate
DATABASE_URL='file:./data/custom.db' pnpm exec prisma db push
DATABASE_URL='file:./data/custom.db' pnpm run build
DATABASE_URL='file:./data/custom.db' pnpm run start
```

## 4. الدروس والشرائح

تدعم المنصة HTML بخطوات مسطحة، HTML بأفكار متداخلة، وReact static build بعد inline للـCSS والـJS. يجب أن تحتوي الشريحة على:

```html
<html lang="ar" dir="rtl">
<script type="application/json" id="slide-manifest">
{
  "lessonId": "fractions-01",
  "title": "الكسور",
  "currentStep": 1,
  "steps": []
}
</script>
```

ويجب أن يرسل controller الرسائل `READY` و`MANIFEST` و`STEP_CHANGED`. كل خطوة يجب أن تطابق `data-step` في HTML، وكل خطوة داخل فكرة يجب أن تحمل `data-idea` الصحيح. عند فشل JSON أو controller، استخدم Console للتحقق من الخطأ بدلاً من افتراض أن الشريحة تالفة.

## 6. السبورة الرياضية

افتح SmartWhiteboard من أدوات السبورة. استخدم الماوس العادي للتفاعل مع زر داخل الشريحة، والقلم للرسم، والتظليل للتأكيد، والممحاة للتصحيح، والليزر للإشارة المؤقتة، والنص للشرح، والأشكال لتوضيح الكسور والهندسة، والسهم والعلامات للتقييم البصري.

الأدوات الحالية تشمل القلم، التظليل، الممحاة، الليزر، النص، الدائرة، المستطيل، المثلث، السهم، صح، خطأ، نجمة، والماوس العادي عند توفرها في الواجهة. تدعم الألوان والأحجام والتراجع والإعادة والمسح. تستخدم السبورة RAF throttling ومزامنة revision وstorage fallback، ولا تُحمل في وضع الطالب.

**تحسينات الأداء (16 أغسطس):** يستخدم القلم الآن **incremental draw** — يرسم فقط القطعة الجديدة من الـstroke بدلاً من إعادة رسم كل الـstrokes في كل حركة، مما يُلغي التأخر (lag) عند الرسم على لوحة مليئة. أداة التحديد (select) تعمل الآن بشكل صحيح بعد إصلاح `pointer-events`. تصدير PNG يدمج **الشريحة + الكتابة** معاً عبر `html2canvas` (بدلاً من الكتابة فقط).

## 7. الطلاب والفصول والمجموعات

يمكنك إنشاء طالب داخل فصل أو بلا فصل، نقله، تغييره، البحث عنه، تسجيل غيابه، إضافته إلى مجموعة، حذف الطالب، أو تقسيم الحاضرين تلقائياً. الطلاب الغائبون لا يظهرون في العجلة ولا في قوائم اللعب ولا في autoSplit ولا في مسارات المكافأة.

النقاط والإجابات والدقة وسجل النشاط والجلسة تحفظ في قاعدة البيانات. الطالب الذي اختير في لعبة يسجل في called-in session حتى تتحقق العدالة قبل إعادة التدوير. الاختيار اليدوي والاختيار العشوائي يخضعان لنفس منطق العدالة.

**العدالة المؤجَّلة (16 أغسطس):** عجلة الطلاب وعجلة الحظ تستخدمان الآن `pickStudentFairDeferred` — تختار الفائز فوراً للعرض البصري، لكن لا تسجّل `calledInSession` إلا بعد اكتمال الدوران. إذا أغلقت النافذة أثناء الدوران، لا يُحسب الطالب كمستدعى.

## 8. الأسئلة ومصادر المنهج

عند تشغيل لعبة منهج، اختر مصدر الأسئلة وعددها:

| المصدر | النتيجة |
|---|---|
| الفكرة الحالية | أسئلة الفكرة المعروضة الآن |
| فكرة محددة | أسئلة idea ID المختار فقط |
| كل الدرس | أسئلة الدرس النشط كله |

يمكن استخدام presets أو إدخال عدد يدوي ضمن الحد المسموح. إذا نفدت أسئلة المصدر المحدد، تظهر رسالة واضحة ولا يوجد fallback صامت. تستخدم الأسئلة stable IDs و`askedQuestionIds` لمنع التكرار داخل الجلسة، بينما يظل shuffle خارج cache.

## 9. الألعاب

تشمل الألعاب الحالية Quick Fire وMath Challenge وQuestion Challenge وQuiz Show وMemory وMystery Box وHot Potato وDice Roll وReaction Time، إضافة إلى عجلة الطلاب وأدوات المجموعة. بعض الألعاب السابقة دُمجت في Question Challenge أو Memory بدلاً من إبقائها نسخاً مكررة.

| الحماية | الغرض |
|---|---|
| answer lock | منع تسجيل إجابتين في نفس الجولة |
| finished/closed refs | منع إنهاء الجولة مرتين |
| selection/reveal lock | منع مضاعفة صندوق أو مكافأة |
| timer cleanup | منع مؤقت يعمل بعد إغلاق اللعبة |
| present-student filtering | منع إشراك طالب غائب |
| markAsked | منع تكرار السؤال الصامت |
| requestExit | تأكيد الإغلاق أثناء جولة نشطة |

قبل بدء الجولة، اختر طالباً حاضراً أو مجموعة حاضرة. بعد النهاية راجع النتيجة قبل منح أي مكافأة إضافية.

## 10. الاحتفالات والتعليقات الافتراضية

يمكن إطلاق confetti أو particles أو كلاهما بحسب إعداد الاحتفال. التعليقات الافتراضية تظهر فقط عند تفعيلها، وتختفي تلقائياً أو بالنقر، ولا تعتبر إجابات حقيقية للطلاب. يمكن تشغيلها من الإعدادات أو باستخدام `Shift+V`.

إذا كانت الجولة بلا فائز إيجابي، لا ينبغي إطلاق احتفال champion. استخدم مؤثرات أخف عند التعادل الإيجابي، واحترم `prefers-reduced-motion`.

## 11. التليبرومبتر والنوتس

يقرأ التليبرومبتر `script` من manifest ويعرضه للمدرس. اكتب script كما سيقوله المدرس، وقسم الجمل بعلامات الترقيم، وضع `notes` للملاحظات الخاصة. يمكن تغيير الحجم والارتفاع وإخفاؤه قبل مشاركة الشاشة في Zoom. النوتس والتليبرومبتر لا يظهران في وضع الطالب.

## 12. Moodle

من MoodlePanel، أدخل URL وtoken وCourse ID و`curriculumKey` ثم نفّذ discovery. استخدم الوسوم:

```text
bisalasa:idea:lesson03:idea01
bisalasa:idea:lesson03:idea02
bisalasa:homework:lesson03
```

تكتشف المنصة Sections والمجموعات والطلاب والأنشطة. تستخدم الوسم أولاً، ثم اسم النشاط، ثم ترتيب النشاط، وتعرض `confidence` و`needsReview`. بعد ذلك تجلب نتائج quiz وassignment وتربطها بالفكرة أو بالدرس كله إذا لم يوجد tag.

المزامنة Delta وت adaptive polling ولا تكتب إلى Moodle. webhook اختياري، ويحتاج relay أو plugin يرسل HMAC صحيحاً. راجع `MOODLE-INTEGRATION-REPORT.md` قبل إعداد Moodle الحقيقي.

## 13. الذكاء الاصطناعي

AI اختياري ويمكن إيقافه بالكامل. أضف مفاتيح provider مع label وpriority وmodel وحالة تفعيل. لا تظهر القيمة الخام للمفتاح بعد الحفظ. استخدم AI لتحليل الدرس، اقتراح الأسئلة، Smart Context، أو أدوات المدرس، ثم راجع الناتج واعتمده قبل عرضه.

الاختبارات الحالية تستخدم mock provider، ولا تعني أن مفتاح Gemini الحقيقي موجود. يجب على مالك المنصة إضافة مفتاحه ومراجعة سياسة إرسال البيانات والحصص ومعدل الطلبات.

## 14. التقارير وTelegram

تجمع التقارير نتائج الألعاب والأنشطة وسجل الطالب والجلسة وMoodle والواجبات. تظهر الأسئلة المرتبطة بفكرة في buckets، وتظهر الأسئلة غير المرتبطة في `lesson_unmapped`. يظهر للمدرس الطالب الذي حل أو لم يحل، ونسبة الإكمال والصحيح والخطأ، وما إذا تم التدخل معه.

يمكن إنشاء PDF عربي وإرساله عبر Telegram عند إعداد التكامل. راجع اتجاه النص والخط والصفحات بعد التوليد. إذا فشل Telegram، يجب أن يبقى التقرير المحلي متاحاً.

## 15. الأداء

الألعاب واللوحات الثقيلة lazy-loaded، وHowler مؤجل، والبحث يستخدم `useDeferredValue`، والقوائم تستخدم `content-visibility:auto`، والأسئلة تستخدم WeakMap caching، وقاعدة SQLite تحتوي فهارس للقوائم وسجل النشاط.

أحدث قياسات QA المحلية في `PERFORMANCE-OPTIMIZATION-REPORT.md`. انخفض chunk صفحة الدخول من 464KB إلى 135KB تقريباً، ووضع الطالب مقاس عند p95 أقل بكثير من الحد المحدد.

## 16. استكشاف الأخطاء

إذا لم تظهر الشريحة، تحقق من امتداد HTML وmanifest وcontroller. إذا لم يظهر script، تحقق من JSON ووجود `script` داخل step. إذا لم يتحرك الدرس، تحقق من `data-step` و`data-idea` ورسائل `postMessage`. إذا لم يعمل الصوت، انقر داخل الصفحة أولاً وتحقق من زر الكتم وسياسة المتصفح.

إذا لم تظهر بيانات بعد استعادة backup خارجية، أعد تحميل الصفحة بالكامل وتحقق من `/api/db/classes.list` و`/api/db/lessons.list`. لا تعتبر شاشة البداية وحدها دليلاً على فشل قاعدة البيانات قبل فحص endpoints.

> **مصادقة API (16 أغسطس):** إذا حصلت على `401 Unauthorized` من أي endpoint، تأكد من استدعاء `/api/auth/whoami` أولاً لضبط الـcookie، أو أرسل الرمز في header `X-Bisalasa-Token`. تنزيل قاعدة البيانات الخام (`/api/backup?format=sql`) معطّل للأمان — استخدم `format=json`.
